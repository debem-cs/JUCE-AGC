# JUCE-AGC — real-time automatic gain control for call audio

Automatic gain control (AGC) for telemarketing call audio, developed for an
integrator-project course at UFSC (2025/1) together with a local audio company.
The company wanted call volume to adjust itself, so that an agent who turned the
volume up during a quiet call would not then hear the next loud call at a
painful level.

The work went in two stages:

1. **MATLAB / Simulink study.** Dynamic range compression (DRC) and AGC were
   modelled in Simulink and compared on speech recordings at different input
   levels. Speech intelligibility was checked with the STOI metric. The
   experiments showed how attack, release, compression ratio, averaging window
   and maximum gain affect the output, and showed that AGC fit the company's
   need.
2. **C++ / JUCE prototype.** The AGC was then implemented as a real-time JUCE
   audio plugin. With a virtual audio cable it can take the computer's sound,
   normalise it and play it back.

## Algorithm

For each channel and each sample `x[n]`, the plugin keeps a log-domain gain `g`:

- **Power estimate.** A moving average of `x²` over a 0.4 s circular buffer.
  Samples below a silence threshold (−50 dBFS) do not update the buffer, so
  pauses in speech do not pull the gain up.
- **Output.** `y[n] = clamp(x[n] · e^g, −1, 1)`.
- **Gain update.** The error between the reference level and the output power,
  in log scale, `e = ln(P_ref) − (ln(P) + 2g)`, updates the gain:
  `g ← min(g + μ·e, g_max)` with `μ = 0.1` and `g_max = 10`.
- **Reference level.** A slider in the plugin window (0–100) sets the target
  level. It is mapped linearly to −50…0 dBFS.

Each channel keeps its own gain, buffer, running sum and buffer index. The
constants are in
[`PluginProcessor.h`](JUCE/projects/AGC/Source/PluginProcessor.h) and the loop
is in `processBlock` in
[`PluginProcessor.cpp`](JUCE/projects/AGC/Source/PluginProcessor.cpp).

## Repository structure

```text
JUCE/
├── projects/AGC/
│   ├── AGC.jucer                 # Projucer project (Visual Studio 2022 exporter)
│   └── Source/
│       ├── PluginProcessor.{h,cpp}   # AGC DSP
│       └── PluginEditor.{h,cpp}      # one slider: reference level
└── VBCABLE_Driver_Pack45/        # VB-Audio virtual cable driver (third-party)
MATLAB/
├── teste-1/   # DRC vs AGC on one speech sample (Simulink: cravoEcanela.slx)
├── teste-2/   # DRC vs AGC at -18 / -24 dB targets on 20 samples, STOI table
├── teste-3/   # Simulink AGC block vs a scripted AGC (AGC_script.slx)
├── teste-4/   # STOI of the scripted AGC vs the JUCE plugin output
└── teste-5/   # digital dB vs sound-pressure (dBA) calibration, reference samples
```

Each `teste-N/` folder has a driver script (`romeuEjulieta.m` or
`romeu_e_julieta.m`), the Simulink model it runs, the input `samples/` and the
processed `.wav` outputs.

## Running

### MATLAB

Requirements: MATLAB, Simulink, Audio Toolbox, and a `stoi` function on the
MATLAB path.

Open MATLAB in one of the `MATLAB/teste-N/` folders and run its script. The
scripts use Windows path separators (`samples\...`), so on Linux or macOS change
them to `/` first.

### JUCE plugin

Requirements: [JUCE](https://juce.com/) with Projucer, and Visual Studio 2022
(the only exporter set up in the `.jucer` file).

1. Open `JUCE/projects/AGC/AGC.jucer` in Projucer.
2. Check that the module paths point to your JUCE installation. The project
   expects `JUCE/modules` four levels above the `.jucer` file.
3. Save to generate `Builds/VisualStudio2022`, then build in Visual Studio.
4. Load the built plugin in a host. To process system audio,
   route the computer's output through a virtual audio cable such as
   [VB-CABLE](https://vb-audio.com/Cable/) and pick it as the plugin input.

`Builds/` and `JuceLibraryCode/` are generated by Projucer and not versioned.

## Limitations

- The step size, maximum gain, silence threshold and dB range of the slider
  are fixed in code. Only the reference level is a user parameter.
- The plugin does not save its state (`getStateInformation` is empty), so the
  reference level resets when the host reloads it.
